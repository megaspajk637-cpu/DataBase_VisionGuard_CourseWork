# Концептуальная модель

## Сущности базы данных
- Operator (Оператор)
- Shift (Смена)
- Camera (Камера)
- Alert (Тревога)
- Detection_rule (Правило детекции)
- Detection_event (Событие детекции)
- Alert_comment (Комментарий к тревоге)
- Alert_history (История тревоги)
- Camera_zone (техническая зона)
- Zone (Смысловая зона)
- ML_model (ML-модель)
- Camera_status_log (История статуса камеры)
- Camera_day_statistics (Статистика камеры по дням)

## Описание связей между сущностями
- Operator-Shift (1 : 0..N): Один оператор может выходить на множество смен, но у каждой смены указан один оператор, который её отработал
- Camera-Shift (1 : 0..N): На одной камере могут проходить разные смены; каждая смена назначена на одну камеру
- Operator-Alert (0..1 : 0..N): Тревога может быть вызвана автоматически, а может быть вызвана оператором вручную. Один оператор может обработать множество тревог, а каждая тревога назначается не более чем одному оператору
- Detection_rule-Alert (0..1 : 0..N): Одно правило может сработать для множества тревог. У автоматически созданной тревоги есть ссылка на сработавшее правило, а у ручной она может отсутствовать
- Detection_event-Alert (1 : 0..1): Одно событие детекции может либо создать одну тревогу, либо не создать ни одной тревоги
- Alert-Alert_comment (1 : 0..N): К одной тревоге может быть добавлено несколько комментариев в процессе её обработки, а каждый комментарий относится к одной тревоге
- Operator-Alert_comment (1 : 0..N): Оператор может оставить много комментариев, но у каждого комментария один автор (оператор)
- Alert-Alert_history (1 : 0..N): У тревоги может быть множество записей о смене статуса; каждая запись истории относится к одной тревоге
- Operator-Alert_history (1 : 0..N): Один оператор может изменить статусы нескольких тревог, а каждая запись истории указывает на конкретного оператора, выполнившего конкретное изменение
- Camera-Camera_zone (1 : 0..N): У камеры есть одна или несколько технических зон с json-полигонами для контроля; во время настройки системы у камеры может быть 0 технических зон; каждая техническая зона относится ровно к одной камере
- Zone-Camera_zone (1 : 0..N): Смысловая зона связана с одной или несколькими техническими зонами (по одной привязке для каждой наблюдающей её камеры); во время настройки системы у смысловой зоны может быть 0 технических зон; каждая техническая зона относится ровно к одной смысловой зоне
- Camera-Detection_event (1 : 0..N): Камера может зафиксировать множество событий детекции, но каждое событие фиксируется одной камерой
- Camera_zone-Detection_event (1 : 0..N): В одной технической зоне (области изображения) может произойти множество событий детекции, но у каждого события детекции указана одна техническая зона (json-полигон), где был замечен объект
- ML_model-Detection_event (1 : 0..N): Одна версия ML-модели может обработать множество событий, но для каждого события фиксируется версия модели, которая его обработала (обнаружила)
- Camera-Camera_status_log (1 : 0..N): У камеры сохраняются все изменения статуса, а каждая запись журнала описывает изменение статуса одной конкретной камеры
- Camera — Camera_day_statistics (1 : 0..N): Для камеры накапливается отдельная статистика за каждый день; каждая дневная запись относится к одной конкретной камере
